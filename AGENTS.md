# Twenty INCONNECT — Codex

## Security and execution boundaries

- **Git is strictly READ-ONLY for Codex.** The user personally performs every Git write: add, commit, push, fetch/pull, switch/checkout, branch/tag changes, merge, rebase, reset, cherry-pick, stash, index/reference changes and worktree operations. Source-edit permission never authorizes Git mutation. Inspect status/log/show/diff only; preserve unrelated and pre-existing work.
- **No infrastructure or PostgreSQL access without action-specific authorization.** This includes read-only session/schema inspection, disposable provisioning, DDL/DML, migrations, generators, Instance/Fast/Slow/Workspace Commands, setup/init/reset, DB-reset integration tests, servers, workers, Redis, BullMQ consumers and external provider calls. Examples, idempotent scripts, green tests and accepted source never authorize execution. Never reset an existing environment. PG0/PG1 physical execution, Stage C5 and operational exact-upgrade remain BLOCKED; do not change the WSL sandbox repair bind mount.
- **Twenty OSS only.** Independently implement INCONNECT with modifiable OSS. Never inspect, copy, derive, adapt, reuse or import Enterprise RLS predicates, evaluators, renderers, builders, entities, migrations or tests. Never modify `engine/core-modules/enterprise/**`.
- **Effective authorization = Twenty standard object/field permissions AND INCONNECT operation policy AND Record Access scope AND Owner Integrity when configured.** `allRecords` omits only the extra INCONNECT row predicate; `not-managed` is no grant. Invalid, ambiguous, missing, corrupt or unavailable required authority denies. Keep access predicates in final SQL before count/search/order/pagination and in the mutation itself; no frontend/in-memory filtering or check-then-write shortcut.
- Derive workspace and human identity from authenticated context. Never accept client-selected workspace/member/Role/authority, discard an authenticated application restriction, impersonate Admin/Supervisor, or invent a generic SYSTEM bypass. Separate human authorization from narrowly authorized technical automation. Historical attribution and known UUIDs grant no current access.
- Work only in the authorized phase. Do not change local Roles, Workspace Members, policies, Teams, memberships, Leads or Folios without authorization for that action. Report requirements needing unauthorized security/schema/data/scope changes before improvising. Unsupported mutation/API paths stay fail-closed.

## Permanent architecture invariants

- INCONNECT adds independent record authorization, teams, Lead distribution and native WhatsApp to Twenty OSS. Executive: own records; Coordinator: own + team; Supervisor/Admin: all subject to standard permissions. Lead/Folio ISO are configured objects with independent owners, no inherited access or synchronization.
- Live metadata determines dynamic object/field/table/schema/owner details. Parameterize values and validate derived SQL identifiers. Never hardcode demo workspace/user/Role/Object/Field/Lead/Folio/Team/membership IDs or physical names. Universal identifiers are import/export/API boundary identities, not persisted policy authority. Preserve composite workspace/object/field references.
- Record-scope owners and assignable destination owners are separate sets. Required Owner rejects explicit null; omission follows configured policy. Transfer validates current record and destination plus standard Owner field permission. Security defaults grant no client permission. `singleActiveMemberOfRole` requires exactly one active candidate, never the first member.
- A member has at most one active Commercial Team membership; a team at most one active Coordinator. Roles and memberships are independent. Historical scope does not imply assignability. Team cache authority is required only for `ownAndTeamRecords`. Never cache actor-specific decisions by workspace + Role.
- PostgreSQL is operational and administrative policy authority; CRM records/live metadata/current permissions are CRM authority. Preserve source-mode contracts: once DB authority is claimed, invalid cache cannot fall back to ENV. Security Redis caches require validated generations, fencing/CAS and fail-closed recovery. Realtime is an authorized invalidation hint; BullMQ is at-least-once transport, never ledger/idempotency/permission authority.
- Keep causal rows, audit, idempotency and Outbox atomic in the specified primary transaction. Honor lock order, fresh post-lock reads, exact runner/connection/transaction and original manager identity. Use the reviewed Core QueryBuilder gateway; never `createEntityManager(queryRunner)` for Core access. Commit publishes buffered effects; rollback discards them. Provider calls/publication follow commit. PostgreSQL and Twilio are not jointly atomic; ambiguous submit stays UNKNOWN without blind retry.
- Preserve decimal-string revisions and PostgreSQL timestamp precision; never round-trip microsecond read/concurrency tokens through JavaScript Date. Errors/timeouts/partial reads/missing dependents are not authoritative absence. Reauthorize current humans and realtime recipients. Retain original idempotent results and referenced keys while replay is admitted; do not invent TTL/purge/workspace deletion.
- Messaging uses centralized authorization and the public Record Access facade; no parallel Owner/Team/permissions, email `modules/messaging` reuse or provider-specific domain authority. Favorite/Unread are personal; Pending shared. Unread arrival order differs from display chronology. CRM context is live/read-only; manual linking confirmed and one-way.
- F13 CREATE grants no READ. Automation principal, business Owner and link provenance are separate. Fresh exact enabled/ready NO_MATCH uses authorized Common Create; UNIQUE links existing; never relink. Physical uniqueness governs concurrency. Same-INSERT snapshots stay internal; caller output narrow.
- Preview grants no transfer authority: revalidate origin/selection/recipients/Roles/permissions/Record Access/Owner/versions before Common Update. No side-effect Folio/Conversation changes or implicit Messaging access. NORMAL/MESSAGE_PENDING needs separate authority and exact linked CRM identity; incomplete tracking is NOT_READY, never NORMAL. TODOS disabled.
- Attention: unique inbound renews PENDING; only authenticated/correlated HUMAN DELIVERED/READ closes still-current frozen coverage. Read/SENT/TEMPLATE format/history do not close it. Preserve intention/revision/coverage/epoch, common Conversation lock and immutable Message origin epoch. Worker activation, historical bootstrap and outbound/manual integration stay gated.

## Code and source validation

- Nx/Yarn 4 monorepo: `twenty-front` (React 18, TypeScript, Jotai, Linaria, Vite, Apollo, Lingui), `twenty-server` (NestJS, TypeORM, PostgreSQL, GraphQL Yoga, Redis/BullMQ), `twenty-shared`, `twenty-ui` and supporting packages. See `package.json`, `nx.json`, `tsconfig.base.json`, `.cursor/rules/`.
- Functional React components, named exports, types over interfaces except third-party extension, string literals over enums except GraphQL, no `any`; composition, props-down/events-up and event handlers over effect-driven state. Follow naming, import order and size conventions in Operations and `.cursor/rules/`.
- Use Jotai/local React state with functional updates and shared type guards. Apollo cache grants no authority. Comments use `//` and explain why; sanitize before formatting; visible UI copy uses Lingui.
- After code changes run focused tests/security regressions, package `lint:diff-with-main`, typecheck, format/whitespace. Preserve GraphQL compatibility; regenerate via codegen after schema changes, audit scope, never hand-edit generated output. Entity changes need reviewed upgrade coverage, never unauthorized generation/execution. Commands need registration and up/down; never rewrite committed up/down.
- Prefer sequential non-destructive checks, bounded Jest in-band and behavior-focused tests; engineering/test details are in Operations. Documentation-only tasks need documentary checks, no product builds/codegen/heavy suites.
- Persist command/scope/source identity, stdout/stderr, exit, test JSON and boot/resources before/after substantial validation; keep resumable status. Missing evidence/interruption is unverified, never PASS. After restart preserve work, inspect evidence and rerun only unverified scope; no automatic full reruns or infrastructure restart.
- At implementation closure report validation/limits, `git status --short` and `git diff --stat`. Distinguish source implemented, ACCEPTED SOURCE-ONLY, physical development test, environment installation, activation and deployment; none implies the next.
- WSL/Linux needs Linux native dependencies. Explicit process environment wins over dotenv; `.env`/`.env.test` are fallback only, never `override: true`. Different database name/port is not physical isolation. Dependencies/upstream require impact review, immutable lockfile discipline and security regressions; no opportunistic upgrades or silent scope expansion.
- Use available/appropriate Context7/MCP; absence alone does not block source work. PostgreSQL MCP requires specific read-only inspection authorization. Syncable-entity skills apply only to real syncable metadata, never ordinary INCONNECT operational configuration/Record Access.
